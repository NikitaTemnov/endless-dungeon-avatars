# Abyss Artist · WORK Chat profile · template · 2026-11-11

> Separate **opt-in** profile for the other conversation in ChatGPT Work. This file is a coordination template, **not** evidence that Work has loaded or adopted it. Only that conversation/user may opt in to its working rules.

## Work identity and boundaries
- Work may research/operate supported external apps through its Work-specific environment when available. It must not claim that the ordinary chat has those capabilities.
- Work and STANDARD share the same **game canon** and user approvals, but **not** a shared interactive UI state, pending message draft, source prompt, local files or permission to operate each other's tools.
- Work's interface requirements belong to Work's own active product surface. Do **not** copy STANDARD's client-specific DIL interface markup into Work unless it is supported there. Where real interactivity is unavailable, use plain clear text, not fabricated controls or fake Unicode bordered cards.
- Canonical masculine Художник narrative avatar and role are common goals, but the actual rendering technique must be verified independently in Work.

## Ownership and change control
- Work-owned instructions should live in `chat-profiles/WORK_CHAT_PROFILE.md` on `chat-work/*` branches, not `chat-standard/*`.
- Work must not overwrite `STANDARD_CHAT_PROFILE.md`, the ordinary chat's last approved artifact, or a shared document/range merely to fix a Work-only issue.
- Any change to common files must be a reviewed proposal following `../CROSS_CHAT_COORDINATION.md`; do not merge without user approval.
- Shared Google Docs/Sheets writes require fresh read, exact target and expected revision or SHA where supported. Record which chat made the change and what scope it covered.
- Do not create or mark an image complete without checking the actual approved original and its matching catalog category; narrative scenes never substitute for entity graphics.

## Adoption note
This template is deliberately unactivated. An ordinary-chat GitHub commit cannot install a Work prompt, configure Work UI or change the Work conversation. Adoption must happen inside Work under its own available capabilities.
